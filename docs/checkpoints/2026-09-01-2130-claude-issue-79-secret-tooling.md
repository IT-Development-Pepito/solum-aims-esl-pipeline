- **The ACL contract was taken from the production validator, not invented.** `WindowsSecretBundlePathValidator` in `config.py` already defined what an acceptable bundle looks like: owner and every ACE limited to the service SID, local administrators, and SYSTEM, with only `ACCESS_ALLOWED` entries. `WindowsFileProtector` writes exactly that as a protected DACL, and a Windows-only test reads the result back through the validator's own `WindowsSecretBundleAclReader`, so the two cannot drift apart unnoticed. When no service SID is configured the writer keeps its own account in the DACL, otherwise a development bundle would be unreadable by the developer who wrote it.
- **Ordering that matters:** the bundle is encoded in memory, written to a temporary file in the same directory, given its ACL, and only then renamed over the final path, so the final path is never visible with permissive permissions even briefly. On any failure the temporary file is removed. An existing bundle that cannot be read is refused rather than overwritten, because one bad write would otherwise discard every other secret.
- **Identity guard, three outcomes:** the process SID is compared with `ESL_SERVICE_IDENTITY_SID` before any write. A mismatch refuses with exit code 2 and says to run as the service account, because under user scope the wrong writer produces a bundle the service cannot read and the read error is deliberately non-disclosing. An unconfigured SID, the development case, warns and proceeds. The expected SID is read from `Settings` when they load and from the environment when they do not, so the guard works on a machine that has only the identity variable set.
- **Connectivity, five outcomes:** `REACHABLE` with the identity the server reports, `UNREACHABLE`, `CREDENTIAL_REJECTED`, `SECRET_UNAVAILABLE`, and `UNCONFIGURED`. Classification unwraps SQLAlchemy's `orig`, reads psycopg's `sqlstate`, reads pyodbc's `args[0]`, and falls back to the two phrases the servers use, so the answer does not depend on which layer raised. No exception text ever reaches output; a fixed sentence per outcome does. URLs are built with `URL.create` from parts, so a password never needs escaping and never renders. `UNCONFIGURED` is not a failure, so the check is useful while access is still being arranged, and the exit code is non-zero for any real failure so it can run unattended. No target may carry an inline password; the fragment after `#` names a bundle key.
- **Two judgement calls, stated rather than assumed.** Audit of a secret change is best-effort: the state store's own password is provisioned with this tool, so the store may be unreachable at exactly that moment; the command warns and still succeeds rather than blocking provisioning on the thing being provisioned. And `secrets list` reports an unreadable bundle without saying why, matching the reader's non-disclosure rule.
