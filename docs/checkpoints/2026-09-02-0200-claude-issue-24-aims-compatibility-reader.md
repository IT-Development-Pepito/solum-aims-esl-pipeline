- **The one contract decision, stated to the owner before implementation.** The displayed page lives only in Core as JSON `currentPage`, the store code only in Portal, so a label is a join across two databases. `currentPage = -1` marks a device with no assignment. `AimsLabel.page` is an `int` with no way to say "no page", so such devices are excluded from `fetch_labels` rather than returned as page minus one, and every exclusion is counted in the audit evidence of the read. This was chosen over widening the port to `int | None`, which would have reopened #22; it is reversible without touching the port.
- **Read-only is enforced twice, and both are tested against a real server.** The engine opens every session with `default_transaction_read_only=on`, so PostgreSQL refuses a write before it consults the role's grants; a test issues a `DELETE ... WHERE false` and asserts the `read-only` refusal. Separately, a query over `pg_class` proves the `esl_aims_reader` role holds no `INSERT`, `UPDATE`, or `DELETE` on any table. The class has no method whose name could issue a write, checked by introspection, but that is the weakest of the three guards and the checkpoint says so.
- **Schema drift is classified, not raised raw.** Before reading, the two relations and four columns the reader depends on are probed with `WHERE false` queries. A failure becomes `AimsSchemaDrift` carrying `FailureSignal(AIMS_COMPATIBILITY, SCHEMA_DRIFT)`, the section 8 matrix row from #20, with the driver message dropped because it can embed the connection string. Tested by pointing the Core side at the state store, which has no `enddevice` table.
