- **Scope:** FR-016 and NFR-011 under AD-003; the section 8 failure matrix rows `AIMS_COMPATIBILITY / UNAVAILABLE` (RETRYABLE) and `AIMS_COMPATIBILITY / SCHEMA_DRIFT` (NON_RETRYABLE). Two defects, both VERIFIED by reading the code against `domain/failures.py` and `application/runner.py`. (1) `_verify_schema` caught every `DBAPIError` and raised `AimsSchemaDrift`, so a connection refusal, timeout, or rejected login during the probe was classified as permanent drift and never retried. (2) `_portal_labels` and `_core_devices` had no mapping, so a driver error there carried no `signal` and the runner recorded it as `unexpected:...:OPERATOR_ACTION_REQUIRED`. Fix: `failure_for(error, relation)` walks the SQLAlchemy `orig` and `__cause__` chain and reads only `sqlstate`; `42P01`, `42703`, and `3F000` mean `AimsSchemaDrift`, anything else means the new `AimsUnavailable`, whose signal is `AIMS_COMPATIBILITY / UNAVAILABLE`. Both carry only the relation name; the driver message is dropped with `from None` because it can embed the connection string. The probe and both reads raise through `failure_for`. Non-goals honored: the matrix, the retry policy, the reader's engine settings, and the mutation adapter (#23) are unchanged. A rejected login is mapped to UNAVAILABLE rather than `CREDENTIAL / EXPIRED` because the matrix defines no credential row for this dependency; that is stated in the issue.
