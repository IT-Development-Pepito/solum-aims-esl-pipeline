Failures: a `StepFailure`, or any adapter error carrying a `FailureSignal`, is classified by the #20 matrix; retryable failures go to `RETRY_WAIT` with the policy's bounded, jittered delay in a `RUN_RETRY_SCHEDULED` event and the scope kept; exhausted or non-retryable ones end in `FAILED` with `step:dependency:kind:class[:attempts_exhausted]`; an unclassified exception is `OPERATOR_ACTION_REQUIRED`, never retried, and recorded by type name only. Restart: `recover_all` marks `RUNNING` executions `RECOVERING`; a run found `RUNNING` is recovered before resuming; the discovered store entry is restored from its checkpoint and the persisted run resumes through #104's durable guard, while the raw reads are repeated at the next attempt number by design (AD-005 keeps raw rows out of the store). `ACTIVE` mode fails terminally before any step until #23. `runtime/worker.py`: `WorkerLoop` picks runnable executions oldest first under `ESL_WORKER_CONCURRENCY`, pauses and resumes with the service, stops by waiting for runs in flight up to the deadline, and runs `recover_all` on start. `runtime/service_host.py`: the host owns the worker like the ticker and records `worker_stopped_in_time`. `runtime/host.py`: `RunnerPorts` (one committed transaction per call, the #104 step in one transaction), `LiveSources` (the four adapters built per call), `build_runner`, `build_worker`, `execution_steps`. `persistence/repository.py`: `get_execution`, `step_history` (latest attempt per step with checkpoints), `configuration_hash_of`, `runnable_executions`. `esl-admin runs show` lists steps and last checkpoints. `config.py`: `worker_concurrency` (1, 1..8).
